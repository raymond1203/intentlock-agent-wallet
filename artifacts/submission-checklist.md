# FP Research Challenge 2026 제출 체크리스트

- 기준 결정문: [`0002-competition-rules-and-deadline.md`](../docs/decisions/0002-competition-rules-and-deadline.md)
- 사용자 확인 제출일: **2026-09-06 KST**. 마감 시각은 주어진 안내에 없으므로 당일 늦게 제출해도 된다고 가정하지 않는다.

이 파일은 **개인 식별 값과 사람의 승인 답변을 기록하지 않는 절차 템플릿**이다. 참가 팀은 2명이며 MetaMask 트랙으로 출전한다. 현재 검수 방식은 담당자 1명과 AI 보조 검토이며 등록 팀 인원과 구분한다. 실제 확인은 팀이 저장소 밖에서 수행하고, 작성된 체크리스트·주소·코드·닉네임·링크·화면 캡처를 GitHub에 커밋하지 않는다. 이미 완료한 참가 신청·팀 구성은 다시 수행할 필요가 없다.

## 제출 파일과 순서

1. `paper/submission-ko.md`를 읽고 핵심 주장·한계·AI 활용 설명을 팀이 최종 승인한다. `paper/final.md`는 분석 원본 연결용 조립본이며 국문 제출용 편집본과 구분한다.
2. 사용자 제공 Four Pillars 예시 템플릿에 맞춘 원고를 공식 Notion CLI로 **새 페이지에 반영했다**. 핵심 요약 3개, 번호가 있는 본문·소제목, 굵은 하위 제목, 표·그림별 Source 표기를 적용했다. 별도의 공식 템플릿 페이지를 복제했다고 주장하지 않는다.
3. **참가 인원 2명**, **참가 트랙 MetaMask**는 반영했다. 사용자 요청대로 대회용 EVM 주소와 학회 코드는 공란이다. 두 값은 실제 Notion에서 직접 채우고 본문에 실명·학회명·저장소 링크를 추가하지 않는다.
4. `figures/ko/`의 네 PNG를 실제 Notion 첨부로 올렸다. 원고 173개 블록·표 9개 전 셀·첨부 이미지 4개의 바이트가 로컬 준비본과 일치하고 읽기 결과의 잘림·미지원 블록은 0건이다. **실제 화면 검수와 Notion 표시 단어 수는 별도**이며, 이번 브라우저 미리보기는 로그인 화면에서 멈췄다.
5. 아래 점검을 마친 뒤 댓글 허용 공유 링크를 익명 계정으로 Admin에게 1:1 전달한다. 공유 범위·수신 확인·제출 시각·최종 내보내기 파일은 비공개로 보존한다.

현재 변경 및 확인 근거는 [`m4-review-template-upload-audit.md`](../docs/experiments/m4-review-template-upload-audit.md)에 있다. Notion 페이지 링크·업로드 식별자·수신 증빙은 저장소 밖에서 관리한다. 아래 항목은 팀의 수동 확인용이며 AI 검증 결과만으로 체크하지 않는다.

## 팀의 최종 확인

- [ ] 최종 Notion에 참가 인원 2명과 MetaMask 트랙이 정확히 반영되었다.
- [ ] 대회용 EVM 주소, 동아리 코드, 익명 오픈카카오톡 설정이 공식 규칙과 맞다.
- [ ] 제출 Notion 상단에 필수 메타데이터가 있다.
- [ ] 실제 Four Pillars 공식 템플릿의 필수 구성과 일치한다.
- [ ] 실명·이메일·학교·동아리명·GitHub 계정·로컬 경로가 없다.
- [ ] MetaMask 트랙의 LLM 보안·형식 검증 초점이 명확하다.
- [ ] Agent Wallet은 practical case study로만 서술된다.
- [ ] 13,000단어 제한 이내다.
- [ ] Callout과 code block이 없고 필요한 코드는 이미지다.
- [ ] 영어 용어의 최초 등장에 한국어·영문 표기가 있다.
- [ ] 모든 주장·수치·인용을 1차 자료와 대조했다.
- [ ] 위반 허용 10/400, 정상 완료 80/160, 첫 API 실패 92/400의 분모·제한을 이해했고, 사후 복구를 주 실험의 성공으로 바꾸지 않았다.
- [ ] 독자적인 분석과 연구자의 의견이 포함되어 있다.
- [ ] 비주장 항목과 조건부 보장 문구를 지켰다.
- [ ] Notion 댓글 권한이 켜져 있고 심사자가 접근할 수 있으며, 별도 브라우저에서 본문·표·그림이 정상 표시된다.
- [ ] 제출 원고에 저장소 링크가 없다.
- [ ] 공식 마감 전에 Admin 1:1로 링크를 전달하고 수신 여부를 확인했다.
- [ ] 제출본과 전송 증빙은 저장소 밖의 팀 보관 위치에 보존했다.

## 익명성 빠른 검사

제출용 내보내기 파일을 대상으로 아래 문자열을 검색한다. 검색 결과와 내보내기 파일의 실제 경로는 커밋하지 않는다.

- 두 팀원의 실명, 닉네임, 이메일, GitHub 아이디
- 학교명, 동아리명, 지역·연구실 식별자
- `github.com`, `localhost`, `C:\\Users`, `/Users/`, `/home/`
- 기존 EVM 주소, ENS, 공개 지갑 주소

검색 결과가 하나라도 남으면 제출하지 않고 Reviewer에게 공유한다.

## 마감 충돌 대응

- 저장소의 자동화와 공개 문서는 공식 블로그의 9월 6일을 보수적 외부 마감으로 사용한다.
- 팀 내부 동결·제출 일정과 운영진 답변은 저장소 밖에서 관리한다.
- 제출 장애 증빙도 익명 계정의 외부 보관 위치에만 저장한다.

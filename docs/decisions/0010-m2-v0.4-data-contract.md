# 0010 — M2 v0.4 terminal allowance data contract

- Status: accepted
- Date: 2026-09-04
- Dataset candidate: 0.4.0
- Supersedes: 0009 only for generated terminal ERC-20 allowance values

## Context

A clean v0.3.0 fork run completed all 80 authored scenarios and reported 80/80 final-goal
`PASS`. Before accepting that run as freeze evidence, the synthetic expected-state rows were also
reconciled against the observed fork post-state. That independent comparison found seven
disagreements, all in `SWAP_BATCH` terminal USDC allowance rows:

| Scenario | Split         | Approved and consumed (USDC atomic units) | v0.3 authored terminal allowance | Observed terminal allowance |
| -------- | ------------- | ----------------------------------------: | -------------------------------: | --------------------------: |
| BS-01    | `TRAIN`       |                                 1,000,000 |                        1,000,000 |                           0 |
| BS-02    | `TRAIN`       |                                 1,500,000 |                        1,500,000 |                           0 |
| BS-04    | `TRAIN`       |                                   800,000 |                          800,000 |                           0 |
| BS-05    | `TRAIN`       |                                 1,200,000 |                        1,200,000 |                           0 |
| BS-07    | `DEV`         |                                   900,000 |                          900,000 |                           0 |
| BS-08    | `DEV`         |                                 1,700,000 |                        1,700,000 |                           0 |
| BS-10    | `HIDDEN_TEST` |                                 1,900,000 |                        1,900,000 |                           0 |

The generator copied the last approval amount into the synthetic terminal state without subtracting
the subsequent matching `transferFrom` consumption represented by the generated transfer effect. The
fork correctly consumed the exact approval, leaving zero. The normal execution oracle still passed;
the separate reference reconciliation is what exposed the self-consistent fixture defect. Therefore,
80/80 execution `PASS` does not make the v0.3.0 dataset or its derived evidence freeze-ready.

This is a generated-state defect, not a change to the intended task. Expected decisions, labels,
oracle comparison semantics, split assignments, pinned quotes and transaction calldata remain
unchanged. Nevertheless, BS-10 was observed in the public legacy `HIDDEN_TEST` split. The minimum
hidden-contamination rule in `benchmark/VERSIONING.md` therefore requires at least a minor version
bump rather than a patch.

## Decision

1. Bump the dataset from 0.3.0 to 0.4.0. Version 0.4.0 supersedes v0.3.0 for M2 claims; it does not
   overwrite or reinterpret the v0.3.0 run.
2. Derive a stored ERC-20 terminal allowance from the ordered effects. Starting at an approval,
   subtract each later transfer whose chain, asset, owner/from account and spender/executing target
   match that approval. Reject generation if consumption exceeds the approved amount. The affected
   exact-input swaps consequently end with allowance zero. Existing explicit revoke, pure approval
   and one-use Permit2 SignatureTransfer semantics remain unchanged.
3. Keep the following benchmark dimensions invariant across the bump:

   | Dimension                      | v0.4 treatment                                                                  |
   | ------------------------------ | ------------------------------------------------------------------------------- |
   | Expected decision and labels   | Unchanged                                                                       |
   | Oracle operators and semantics | Unchanged; only the generated terminal allowance value is corrected             |
   | Train/dev/legacy-hidden splits | Unchanged                                                                       |
   | Quote and slippage inputs      | Reuse `swap-quotes-v0.3.json` byte-for-byte as a pinned dependency              |
   | Action ordering and calldata   | Unchanged                                                                       |
   | Terminal allowance expectation | Approval minus later matching `transferFrom` consumption; zero for the BS cases |

4. Invalidate the v0.3.0 M2 execution artifact, the v0.3.0 LLM baseline and every freeze candidate
   derived from either one. Preserve them only as diagnostic provenance, clearly marked
   pre-correction and ineligible for headline metrics or freeze.
5. From one clean, committed v0.4.0 candidate, rerun the complete 80-scenario M2 execution and the
   LLM baseline. Partial reuse of v0.3.0 decisions or execution rows is not accepted.
6. Regenerate the blinded review material and obtain two independent human submissions for the exact
   v0.4.0 candidate. Prior review material cannot approve the new candidate by implication. No human
   review is complete at the time of this decision.
7. Make zero synthetic reference disagreements an explicit completion and freeze gate, in addition
   to complete clean execution, oracle/reference checks and the two-person review gate.

## Alternatives

- **Publish v0.3.0 because the execution oracle passed 80/80.** Rejected: this would ignore a direct
  mismatch between authored terminal state and observed chain state and would allow a
  self-consistent generator/oracle error into the benchmark.
- **Release 0.3.1 as a narrow fixture patch.** Rejected: the correction can change evaluation input,
  and BS-10 was inspected in the legacy hidden split. The version policy requires at least a minor
  bump after hidden-test contamination.
- **Change the allowance oracle or labels.** Rejected: the intended invariant is still the actual
  terminal authorization. Only its generated value was wrong; decisions, labels and oracle meaning
  remain valid.
- **Recapture quotes or change calldata while regenerating.** Rejected: neither caused the defect.
  Byte-preserving reuse isolates the allowance correction and keeps the v0.3/v0.4 comparison
  attributable.

## Consequences

- All generated base scenarios, mutations, manifests and review packets become v0.4.0 artifacts even
  though only the terminal allowance derivation changes.
- The clean v0.3.0 80/80 run remains useful evidence that led to defect discovery, but it is not valid
  M2 completion evidence. Its LLM output and freeze candidate are invalid for the same reason.
- Full fork execution, the LLM baseline and two-person review must be paid again. This cost is
  necessary because every downstream artifact is bound to exact dataset bytes and candidate hashes.
- Keeping decisions, labels, splits, quotes and calldata fixed makes the correction auditable and
  limits experimental drift.
- M2 remains incomplete until the v0.4.0 run has 80 complete authored-fixture passes, zero synthetic
  reference disagreements, a version-matched LLM baseline and two valid independent human reviews.
  This ADR does not claim that the human-review gate has been satisfied.

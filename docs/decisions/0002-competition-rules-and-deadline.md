# 0002 — 대회 규칙, 마감, 익명성, 공개 정책

- 상태: 팀 외부 절차 확인, 문서 리뷰 대기
- 결정일: 2026-08-17 KST
- Owner: `@raymond1203`
- Reviewer: `@billy-baek`
- 관련 Issue: #6

## Context

FP Research Challenge 2026 안내의 제출 일정이 서로 일치하지 않는다. 공개 Notion의 일정 표에는 연구 작성·제출 기간이 `08/03–09/13`으로 적혀 있고, 같은 페이지의 주의 문구에는 `09/06 리서치 제출 기한 엄수`, 제출 안내에는 다시 `09/13`이 적혀 있다. Four Pillars 공식 블로그는 제출 마감을 `09/06`으로 안내한다.

익명성 규칙을 위반하거나 늦은 날짜를 믿고 작업하면 내용과 무관하게 실격·미제출 위험이 있다. 따라서 운영진의 정정 전까지 더 엄격한 규칙을 적용한다.

## Decision

### 일정

- 공식 외부 마감은 **2026-09-06 KST**로 취급한다.
- 팀 내부 동결·제출 일정은 두 팀원이 저장소 밖에서 관리한다.
- 운영진과 주고받은 답변의 원문, 계정, 화면 캡처는 저장소에 기록하지 않는다. 공식 공지가 바뀌면 공개된 근거만 이 결정문에 반영한다.

### 트랙 적합성

- MetaMask 트랙의 본 주제는 `LLMs for Security, Formal Verification, or AI-assisted Smart Contract Security`이다.
- Agent Wallet은 **실제 적용 사례(practical case study)**로만 위치시킨다.
- 논문의 주 기여는 멀티 툴 LLM 에이전트의 보안·런타임 검증이며, 특정 Agent Wallet 제품 구현 자체가 아니다.

### 익명성

- 대회용 신규 EVM 주소를 만들고 이를 팀 이름으로 사용한다.
- 주소를 개인·학교·동아리·기존 지갑·ENS·SNS와 연결하지 않는다.
- 동아리 코드는 `1000–9999` 중 하나를 사용하며 실제 동아리명을 공개하지 않는다.
- 오픈카카오톡 닉네임은 EVM 주소 앞 8자리로 사용한다.
- 제출 Notion 상단에는 EVM 주소, 참가 인원, 트랙, 동아리 코드만 적는다.
- 제출 원고와 메타데이터에서 실명, 이메일, GitHub 계정, 로컬 경로, 학교·동아리 식별자를 제거한다.
- 팀은 참가 신청과 익명성 설정 등 외부 수작업을 완료했다고 확인했다. 실제 주소·코드·닉네임·링크·증빙은 이 저장소에서 수집하거나 보관하지 않는다.

### 제출 형식

- 팀 인원은 2–4명이다. 실제 참가 인원은 제출용 Notion에서만 관리한다.
- 한국어 원고는 안내상의 최대 `13,000단어`를 넘지 않는다.
- Notion 제출만 허용되는 것으로 운영한다.
- 최종 페이지는 댓글을 허용한 공유 링크로 만들고, 익명 오픈카카오톡에서 Admin 1:1로 전달한다.
- Callout과 code block은 사용하지 않는다. 코드 설명은 이미지로 변환한다.
- 자연스러운 한국어 번역이 가능한 영어 용어는 한국어를 우선하고, 최초 등장 시 영문을 함께 적는다.
- 단순 자료 집계보다 연구자의 독자적인 분석과 의견을 분명히 포함한다.
- AI 사용은 허용되지만 모든 사실·수치·인용은 사람이 1차 자료와 대조한다.

### 저장소·공개

- 심사 종료 전 저장소는 비공개로 유지한다.
- 제출 원고에 GitHub 저장소 링크나 계정명을 넣지 않는다.
- 재현성 자료 공개는 결과 발표 이후, 익명성 해제와 공개 가능 여부를 운영진에게 확인한 뒤 진행한다.
- 모든 팀이 연구를 공개할 수 있다는 안내는 출판 가능성을 뜻하지만, 심사 중 익명 저장소 공개 허가로 해석하지 않는다.

## 정보 최소화 원칙

- GitHub에는 공개된 대회 규칙과 연구에 필요한 결정만 기록한다.
- 팀 식별 값, 참가·연락 계정, 제출 링크, 운영진 대화, 작성된 외부 체크리스트를 기록하지 않는다.
- 외부 수작업의 완료 여부는 팀의 확인으로 충분하며, 저장소 evidence를 요구하지 않는다.
- 저장소 자동화에 날짜가 필요하면 공개된 공식 마감만 사용한다.

## Alternatives

- **9월 13일을 마감으로 채택:** 같은 Notion에 근거가 있지만 공식 블로그와 엄수 문구에 반하므로 기각했다.
- **8월 2일 이후 등록 불가로 해석:** 공식 블로그 일정과 Notion의 `수시 참여 가능`이 충돌한다. 이미 참가 절차를 진행하는 팀에는 직접 영향이 없으며, 신규 등록이 필요하면 운영진 확인 전에는 가능하다고 가정하지 않는다.
- **심사 중 공개 저장소 사용:** 익명 주소와 GitHub 신원을 연결할 수 있어 기각했다.

## Consequences

- 공개용 아티팩트와 익명 제출본은 별도로 관리해야 한다.
- [`artifacts/submission-checklist.md`](../../artifacts/submission-checklist.md)는 값이나 상태를 커밋하지 않는 절차 템플릿으로만 사용한다.

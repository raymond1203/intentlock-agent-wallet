## 리뷰 판단과 반영

[#35 팀원 재감사](https://github.com/raymond1203/intentlock-agent-wallet/issues/35#issuecomment-5552798124)는
스스로 AI 보조·비독립 검토임을 명시한다. 두 번째 독립 인간 검수 또는 최종 저자 승인으로 계산하지 않는다.
팀원이 보고한 URL·인용 전수 검사를 이번에 새로 수행한 검사처럼 표시하지도 않는다.

유일한 수정 요청인 6.1 표의 혼합 분모를 별도 산술로 확인했다. LLM 오거부는 58/160=36.25%,
Guard Mode 판단 유보는 147/400=36.75%, IntentLock 판단 유보는 65/400=16.25%, 확인 요구는
80/400=20.00%다. 다섯 시스템의 해당 세 지표는 원본 집계와 일치했다.

표 열에 비적대적 160건과 전체 400건을 명시했다. 비적대적 집합에 정상 원본 80건과 의도 이탈 80건이
함께 포함된다는 설명, 확인 요구가 실제 사람 응답 횟수가 아니라는 설명도 표 가까이에 뒀다.
보안·정상 완료 표와 구성요소 표의 400/160 분모도 같은 기준으로 명시했다. 수치나 실행을 바꾸지 않았다.

## CLI 업로드와 사후 검증

사용자는 새 페이지 생성과 미제공 필드 공란을 명시적으로 요청했다. 이미 인증된 공식 Notion CLI 0.21.7을
사용해 새 최상위 페이지에 네이티브 본문·목록·제목·표·이미지 블록을 생성했다. 기존 페이지는 건드리지 않았다.
CLI의 기본 파일 생성은 무료 플랜에서 다중 분할 업로드를 거부했으므로, 동일 CLI의 공개 API 명령으로
각 5 MB 미만 PNG를 single_part 방식으로 업로드했다. 유료 플랜 전환이나 별도 권한 확대는 하지 않았다.

저장 후 CLI로 전체 블록과 각 표의 행을 페이지네이션 조회했다.

- 본문 173개 블록: 유형·순서·전 텍스트·굵은 표시·인용 링크가 업로드 계획과 일치.
- 표 9개: 전 셀의 텍스트·링크·표 머리글 속성이 일치.
- 이미지 4개: 실제 Notion 파일 첨부이며 첨부 원본을 읽어 계산한 SHA-256이 각 로컬 PNG와 일치.
- 제목, 참가 인원 2명, MetaMask와 두 공란 유지 확인.
- Markdown 재조회에서 truncated=false, 미지원 블록 0개. 코드·콜아웃을 생성하지 않았다.

페이지 URL, 파일/블록 식별자, 원본 재조회 자료와 정확한 작업 시각은 저장소 밖 비공개 기록에만 보존했다.
GitHub에서 팀 EVM 주소·학회 코드·Notion 링크를 연결하지 않는다.

## 남은 수동 확인

브라우저 미리보기는 Notion 로그인 화면으로 이어졌다. 실제 문서 화면을 보지 못했으므로
렌더링 검수와 Notion 표시 단어 수를 확인했다고 주장하지 않는다. 팀이 다음을 수행한다.

1. 새 페이지에서 팀 EVM 주소와 학회 코드를 채우고 고유 신원 연결 가능성을 검수한다.
2. 원고 내용·한계·AI 활용을 최종 승인한다.
3. 실제 Notion에서 제목/표/그림·13,000단어 이내·댓글 허용·익명 접근을 확인한다.
4. 익명 닉네임으로 Admin에게 전달하고 수신·제출 시각·내보내기 파일을 비공개로 보존한다.

공유 권한은 변경하지 않았고 대회 제출은 수행하지 않았다. 따라서 #35는 열린 상태로 유지한다.

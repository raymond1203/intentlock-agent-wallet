# Four Pillars 독자용 편집 검토

검토일: 2026-09-06. 대상은 동결 실험 이후의 **출판 편집**이다. 연구 설계·결과·실패 기록을
변경하거나 실험을 다시 수행하지 않는다. 아래는 공개 글에서 관찰한 방식과 본 연구의 편집 판단을
구분한 기록이며, Four Pillars 내부 심사 기준·공식 스타일 가이드로 제시하지 않는다.

위 표본은 발행물 전체의 통계적 표본이 아니다. 글 종류와 작성자에 따라 목차, 문장 길이와
요약 항목 수가 다르다. [Tech 연구자 소개](https://research.4pillars.io/en/researchers/jay)의
기술 구조와 실제 적용 가치를 다양한 독자에게 설명한다는 공개 방향도 참고했다.

## 관찰과 적용

1. **문제에서 시작한다.** 프레임 트랜잭션 글은 기존 구조의 제약을 먼저 설명한다. 우리 글도
   구현 목록보다 같은 자산 100 단위 한도에 60 단위 호출 두 개를 대입하는 예시가 먼저 필요하다.
   이 예시는 실제 피해 사건이나 실험 관측이 아니라고 명시한다.
2. **요약이 결론을 담는다.** Monthly EIP의 요약은 목차 안내에 머물지 않는다. 우리 요약에는
   누적 효과를 검사해야 하는 이유, 400건과 160건으로 나눈 실제 결과, 사후 발견의 한계를 둔다.
3. **구조 설명 뒤에 판단을 붙인다.** 프레임 트랜잭션과 ERC-8128처럼 역할과 검증 순서를
   설명한 뒤 그 구조가 해결하는 문제를 말한다. 우리 그림은 선택적 계약 생성, 측정한 재생 평가,
   별도 지갑 연결 모듈을 분리한다. 세 경로가 하나의 실측된 전체 시스템으로 오인되지 않아야 한다.
4. **관점을 결과에 연결한다.** Monthly EIP의 마지막 논평은 앞의 목록과 구분된다. 우리 결론은
   막연한 안전성 강조 대신, 위임 단위를 개별 호출에서 승인된 작업의 경제적 범위로 바꾸자는
   설계 판단을 드러낸다. 이는 본 연구의 주장이지 Four Pillars의 공식 입장이 아니다.
5. **독자의 해석 오류를 먼저 막는다.** 우리 실험의 50% 정상 완료는 정상 원본 80건과 의도
   이탈 80건을 합친 구성에서 나온다. 실제 업무 절반이 실패한다는 뜻이 아니다. 오류 분류 75건과
   위반 허용 10건도 다른 지표다. 이런 차이는 면책 문장만 반복하지 않고 그림의 제목·분모에 넣는다.

## 문체 수정의 기준

현재 원고는 검증 로그, 긴 영문 병기, 반복된 부정형 한계 설명이 독자에게 주장을 전달하는
문장보다 두드러진다. 이를 곧바로 AI 작성 여부의 증거로 볼 수는 없다. 개정은 AI 탐지 회피나
저자 경험의 창작이 아니라, 중복을 줄이고 구체적인 원인·관측·판단을 연결하는 편집이다.

- 긴 논문식 제목과 요약 뒤의 중복 초록을 독자용 제목·짧은 도입으로 바꾼다.
- 형식적인 절 제목과 나열을 질문·주장 중심으로 바꾸되 표의 데이터 셀은 그대로 둔다.
- 자동 생성된 음의 결과 목록이 비었다는 문구보다 실제 남은 비용과 실패를 먼저 설명한다.
- AI 활용 고지, 1명+AI 보조 검수, 독립 인간 검수 미수행 설명은 유지한다.
- 제안한 판단은 최종 저자가 검토해야 한다. 실제로 하지 않은 경험·회의·승인·제출을 쓰지 않는다.

## 시각 디자인의 범위

공개 본문의 도식 배치와 출처 표시는 확인했다. 브라우저 연결과 원본 이미지의 콘텐츠 형식
제한으로 웹 이미지의 직접 검수가 어려웠으나, 사용자가 후속 메시지로 참고 장표 5점을 제공했다.
이 캡처에서 다음 시각적 특징을 직접 확인했다. 이는 제공된 표본의 특징이지 전체 발행물의
공식 디자인 토큰·정확한 색상값·폰트 이름을 확인했다는 뜻은 아니다.

- 누적 막대와 흐름 장표: 거의 검은 배경, 큰 흰 제목, 낮은 대비의 원형 배경, 파스텔 계열,
  특정 항목의 청록 강조, 회색 보조축, 하단 출처·기준일 영역.
- 코드 이미지: 어두운 코드 면과 바깥 여백. 우리 글에서는 코드 장식 자체를 넣기보다 실행
  순서를 도식화한다. 코드 설명이 꼭 필요한 경우에도 대회 규정대로 이미지여야 한다.
- 정밀 비교 그래프: 밝은 배경, 두 개의 비교 패널, 눈금·범례·기준선. 모든 그림을 어둡게
  통일하는 것이 이 표본의 공통 규칙은 아니다.
- 표지: 어두운 기하학적 패턴과 큰 주제 표식. 데이터 설명 장표와 표지의 역할을 분리한다.

개정판은 검은 연구 장표와 밝은 정밀 비교 그림을 용도에 따라 사용한다. 파스텔 보조색,
청록 강조, 큰 한글 제목, 하단 출처 영역을 반영하되 Four Pillars 로고·워터마크·공식 발행
표식이나 타인의 장표 구성·데이터를 복제하지 않는다. 표지는 본 연구의 누적 실행이라는 주제를
독자적인 그래픽으로 표현한다.

| 장표             | 전달할 질문                                       | 데이터 보호                                           |
| ---------------- | ------------------------------------------------- | ----------------------------------------------------- |
| 누적 예산 예시   | 호출별 허용이 전체 요청을 지키는가?               | 100·60·120은 설명용 숫자이며 실험과 분리              |
| 구현과 측정 경계 | 무엇을 설계했고 무엇을 실제 측정했는가?           | 계약 확인·분산 원장·일괄 서명 동결의 미구현 범위 명시 |
| 보안·정상 완료   | 위반 감소와 정상 완료 개선은 같은가?              | 같은 0–100% 축, 95% 구간, 400/160 분모, 동률 유지     |
| 오류 분류        | 오류 건수를 손실이나 위반 허용으로 읽어도 되는가? | 기존 분류 합계와 대표 유형만 표시, 재분류 없음        |
| 판단 지연        | 측정 경로의 시간이 얼마나 다른가?                 | 전체 축과 별도 확대 축을 명시, 원래 밀리초 값 보존    |

수치 그림은 기존 결과 JSON에서 생성하는 SVG와 PNG 파생물이다. 원본 그래프와 동결 결과는
수정하지 않는다. 제공된 캡처의 분위기와 본 연구 데이터의 읽기 정확도를 함께 대조한다.

## 대회 규정이 우선하는 항목

일부 공개 웹 글의 코드박스·세부 제목 형식을 그대로 대회에 적용하지 않는다. 사용자 제공 제출
조건인 메타데이터 네 항목, Key Takeaways 3개, 번호 제목, 이미지별 출처, 코드박스·콜아웃 금지,
국문 13,000단어 한도를 우선한다. 팀 EVM 주소와 학회 코드는 공란으로 유지한다.

## 산출물과 확인 경계

개정판은 `paper/editorial-ko.md`, 장표는 `figures/editorial/`에 생성한다. 기존
`paper/submission-ko.md`와 Notion 페이지를 자동으로 덮어쓰지 않는다. 개정판의 표·인용·기존
산출물 무결성과 그림의 실제 렌더링을 검사한 뒤 저자가 문체와 관점을 확인한다. Notion 실제
단어 수, 게시 화면, 댓글·익명 공유와 제출은 이 로컬 편집 검사의 완료에 포함되지 않는다.
